# ChatGPT Card Manager v0.4

本地运行的 Chrome / Edge Manifest V3 扩展，用卡片方式批量管理 ChatGPT 历史对话。

## v0.4：重点降低 429 风险

这一版不再把“读取所有卡片正文”当作正常路径，而是改成“列表先展示 + 本地缓存优先 + 极低速预读 + 悬停按需读取”。

### 1. IndexedDB 本地正文缓存

- 第一次成功读取某个对话后，把正文、创建时间和列表更新时间写入浏览器本地 IndexedDB。
- 以后重新打开 Chat Deck 时，优先从本地缓存恢复，不再次访问详情接口。
- 如果列表返回的 `update_time` 表明对话后来又被修改，缓存才会视为过期。
- 如果没有更新时间可比对，缓存默认软有效期为 7 天。
- 删除/归档后会同步删除对应的本地缓存。

### 2. 详情接口不再高速后台扫全屏

- 正文详情始终只有 **1 个并发**。
- 普通详情请求最小间隔提升到约 **2.6 秒**。
- 后台预读最多只排队 **3 张**当前真正可见的卡片。
- 后台预读之间至少间隔约 **7 秒**。
- 悬停 500ms 后展开的卡片拥有最高优先级。
- 鼠标在 500ms 内移走，不会产生详情请求。
- 用户离开尚未开始请求的展开卡片时，会取消该排队任务。
- 页面切到后台标签页时暂停详情队列。

### 3. 429 后进入“安全模式”

任何一个请求出现 HTTP 429 后：

- 优先遵守服务端 `Retry-After`。
- 没有 `Retry-After` 时采用更保守的指数退避，默认从约 12 秒级开始。
- 自动提高后续同类请求间隔。
- **后台预读直接暂停 30 分钟**；这段时间只在用户主动悬停时按需读取。
- 冷却时间写入 `localStorage`，刷新 ChatGPT 或重新加载扩展后仍继续生效，不会因为刷新页面又马上开始轰接口。

### 4. 多 ChatGPT 标签页共享限速

v0.4 会在同一浏览器里的 ChatGPT 标签页之间共享最近请求时间和 429 冷却时间；支持的浏览器还会通过 Web Locks 对请求时隙进行串行预留，降低两个标签页同时请求造成的瞬时突发。

### 5. 列表和删除/归档也统一限速

- 会话列表请求最小间隔约 **1.8 秒**。
- 滚动到底部后增加防抖，不会连续触发多次“加载下一批”。
- 删除/归档不再使用固定 800ms 连续循环，而是统一经过安全调度器；写操作最小间隔约 **2.2 秒**，遇到 429 同样自动冷却。

## 展开阅读

延续 v0.3：

- 鼠标停留 500ms 才展开。
- 浮层约占 3 列 × 2~3 行普通卡片，即约 6~9 张卡片面积。
- 不改变原 Grid 布局，不挤动其他卡片。
- 背景只做轻微模糊。
- 左侧显示对话速览，右侧显示消息时间线。
- 未缓存对话会显示安全限速读取动画；读取成功后立即写入本地缓存。

## 为什么仍不能保证“绝对不会 429”

扩展调用的是 ChatGPT Web 自己使用的内部接口，并不是面向第三方公开且有稳定配额说明的 API。限流阈值可能随账号、时间、服务端策略变化。因此 v0.4 的目标是把请求模式从“批量突发”改成“缓存优先 + 串行 + 慢速 + 自适应退避”，从工程上显著降低触发概率，并在触发后立即停止后台流量。

## 安装 / 更新

1. 解压 ZIP。
2. Chrome 打开 `chrome://extensions/`；Edge 打开 `edge://extensions/`。
3. 开启“开发者模式”。
4. 首次安装：点击“加载已解压的扩展程序”。
5. 已安装旧版：建议用 v0.4 目录覆盖旧目录，然后点击“重新加载”。
6. 刷新 `https://chatgpt.com/`。

> 如果 v0.3 已经触发 429，服务端已有的限流不会因为升级而立即消失。升级后先等待当前服务端冷却结束；v0.4 会记住后续 429 的冷却状态。
